## 1. Назначение проекта

Работающий прототип хранилища пользовательских сессий на NoSQL-СУБД **Redis**. Сессия хранится в структуре **Hash** с ограниченным сроком жизни (**EXPIRE/TTL**). Реализованы вход, проверка, продление, выход, отзыв одной и всех сессий пользователя, просмотр активных сессий и автоматическое удаление просроченных сессий.

Обоснование выбора технологии (сравнение с PostgreSQL и MongoDB) приведено в [`docs/ADR.md`](docs/ADR.md).

## 5. Быстрый запуск (5 действий)

Команды выполняются в терминале из корневой папки проекта.

```bash
# 1. Запустить Redis
docker compose up -d

# 2. Создать файл настроек
cp .env.example .env

# 3. Заполнить хранилище тестовыми данными (40 сессий)
mvn -q compile exec:java -Dexec.mainClass=kz.sro.sessions.Seed

# 4. Выполнить демонстрационные запросы (Q1–Q12)
mvn -q compile exec:java -Dexec.mainClass=kz.sro.sessions.Demo

# 5. Запустить автоматические тесты
mvn test
```

Все шаги подряд можно выполнить одной командой: `bash scripts/run_all.sh`.

## 6. Подробная инструкция

### 6.1. Запуск Redis

**Вариант А. Командой.** В корне проекта выполнить `docker compose up -d`. Проверка работы:

```bash
docker exec -it redis-sro redis-cli ping
```

Ожидаемый ответ: `PONG`.

**Вариант Б. Через интерфейс Docker Desktop.**

1. В строке поиска ввести `redis`, выбрать образ **Docker Official Image**, нажать **Pull**.
2. На вкладке **Images** нажать **Run** у образа `redis`, раскрыть **Optional settings**.
3. Указать имя контейнера `redis-sro` и порт хоста `6379`, нажать **Run**.
4. На вкладке **Containers** контейнер `redis-sro` должен иметь статус **Running**.

Если контейнер `redis-sro` уже создан вручную, команду `docker compose up -d` выполнять не нужно: достаточно запустить существующий контейнер (`docker start redis-sro`).

### 6.2. Настройки подключения

Файл `.env` создаётся копированием шаблона (`cp .env.example .env`). Он не публикуется в репозитории.

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| `REDIS_HOST` | `localhost` | Адрес Redis |
| `REDIS_PORT` | `6379` | Порт Redis |
| `REDIS_PASSWORD` | *(пусто)* | Пароль (для локального стенда не требуется) |
| `REDIS_DB` | `0` | Номер базы для Seed и Demo |
| `SESSION_TTL_SECONDS` | `1800` | Срок жизни сессии, секунд |

Если порт 6379 занят, запустите Redis на другом порту (например, `6380:6379`) и укажите его в `REDIS_PORT`.

### 6.3. Заполнение данными (Seed)

```bash
mvn -q compile exec:java -Dexec.mainClass=kz.sro.sessions.Seed
```

Скрипт удаляет прежние ключи `session:*` и `user_sessions:*` и создаёт **40 синтетических сессий** для 10 тестовых пользователей (`user_01` … `user_10`). Каждая 5-я сессия создаётся с TTL 60 секунд, каждая 7-я отзывается. Адреса клиентов взяты из приватного диапазона `10.0.0.x`; реальные персональные данные не используются.

Ожидаемый результат: `Inserted sessions: 40`.

### 6.4. Демонстрационные запросы (Demo)

```bash
mvn -q compile exec:java -Dexec.mainClass=kz.sro.sessions.Demo
```

Программа выполняет 12 запросов:

| № | Операция | Назначение |
|---|---|---|
| Q1 | `login` | Создание сессии |
| Q2 | `validate` | Проверка сессии по ID |
| Q3 | `ttlRemaining` | Остаток TTL |
| Q4 | `touch` | Продление сессии |
| Q5 | `activeSessions` | Активные сессии пользователя |
| Q6 | `countActive` | Число активных сессий |
| Q7 | `revoke` | Отзыв сессии |
| Q8 | `logout` | Удаление сессии |
| Q9 | `revokeAllForUser` | Отзыв всех сессий пользователя |
| Q10 | `statsByStatus` | Нетривиальный: статистика по статусам |
| Q11 | `topUsers` | Нетривиальный: топ пользователей по числу активных сессий |
| Q12 | замер `validate` | Проверка требования «быстрее 10 мс» |

Пример вывода (идентификатор сессии случайный, значения Q6, Q10 и Q11 зависят от момента запуска, так как часть сессий уже истекла):

Сообщения `SLF4J: Failed to load class ...` носят информационный характер (не настроен логгер) и на работу программы не влияют.

### 6.5. Автоматические тесты

```bash
mvn test
```

Тесты выполняются в **отдельной базе Redis №1** и не затрагивают данные базы №0. Ожидаемый результат: `Tests run: 5, Failures: 0, Errors: 0`.

| № | Сценарий | Тест |
|---|---|---|
| T1 | Вход пользователя | `loginCreatesValidSession` |
| T2 | Выход пользователя | `logoutInvalidatesSession` |
| T3 | Отзыв сессии | `revokedSessionIsInvalid` |
| T4 | Истечение TTL (1 с) | `expiredSessionIsInvalid` |
| T5 | Отзыв всех сессий пользователя | `revokeAllForUserWorks` |

Тест T4 ожидает 1,5 секунды, поэтому общее время выполнения около 2 секунд.

## 7. Проверка данных в Redis

### 7.1. Через консоль контейнера

Docker Desktop → **Containers** → `redis-sro` → вкладка **Exec** → выполнить `redis-cli`, затем:

```
KEYS session:*
HGETALL session:<идентификатор из списка KEYS>
TTL session:<идентификатор>
SMEMBERS user_sessions:user_01
DBSIZE
```

### 7.2. Через Redis Insight

Подключение: хост `localhost`, порт `6379`, пароль пустой. В папке `session` находятся Hash сессий (поля и TTL), в папке `user_sessions` — Set идентификаторов сессий пользователей.

### 7.3. Демонстрация автоматического истечения

1. Сразу после запуска `Seed` выполнить `DBSIZE` и записать значение.
2. Подождать более 60 секунд (сессии с TTL 60 с истекают) и выполнить `DBSIZE` повторно.
3. Число ключей уменьшится: Redis удалил просроченные сессии самостоятельно (требование FR8). Отозванные сессии сохраняются 300 секунд для аудита, затем также удаляются.

## 8. Модель данных

| Ключ | Тип | Содержимое |
|---|---|---|
| `session:{uuid}` | Hash + TTL | `userId`, `ip`, `userAgent`, `status` (ACTIVE / REVOKED), `createdAt`, `lastAccessAt` |
| `user_sessions:{userId}` | Set | Идентификаторы сессий пользователя (индекс для отзыва всех сессий и списка активных) |

## 9. Остановка и очистка

```bash
docker compose stop            # остановить Redis (данные сохраняются до удаления контейнера)
docker compose down            # остановить и удалить контейнер (данные удаляются)
docker exec -it redis-sro redis-cli FLUSHALL   # очистить все данные
```

Контейнер создан без постоянного тома, поэтому после удаления данные пропадают. Для восстановления достаточно повторно запустить `Seed`.
